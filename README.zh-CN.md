# ReproFig

[English](README.md) | **简体中文**

**从论文图件到可验证、可追溯的科研复现工作流。**

ReproFig 是一个面向 Codex 的科研复现 Skill。它以科学论文中的图件为入口，走进生成这些结果的研究过程。给它一篇论文和一至三张目标图，它会理解每张图展示的内容及其在论文论证中的作用，还原生成该图所需的数据、方法、参数与绘图流程，评估现有证据，并将静态发表结果转化为可理解、可执行、可验证、可追溯的科研复现任务。

ReproFig 要复现的是研究过程及其关键科学现象，而不是已发表图片的像素。在研究者批准一条有证据支持的路线后，它可以执行复现，依据科学标准验证结果，并交付代码、配置、日志、环境记录和溯源信息，使整个过程能够被检查、重新运行或继续拓展。

复现出一张图不是终点。更重要的是建立一座有记录、有证据的桥梁，让研究者能够从已发表结论返回研究过程，理解它、质疑它、调整它，并在此基础上继续研究。

> 理解证据，重建过程，检验论文主张。

## ReproFig 能做什么

1. **理解图件作为科学证据的意义。** 阅读图注、坐标轴、图例、子图、邻近正文、公式、方法与补充材料，说明图中展示了什么，以及它支持论文中的什么论点。
2. **还原图件的生成过程。** 梳理输入数据、预处理、方法实现、参数、随机化过程、统计步骤、绘图协议，以及不同图件之间的依赖关系。
3. **制定有证据支持的复现路线。** 综合论文、代码、数据、公开来源与本机现有能力，区分哪些条件已核验、可推导、可合理假设、缺失或不需要；为每张图确定一个有依据的复现等级，并说明每条候选路线的科学范围与边界。
4. **执行并验证研究过程。** 经研究者批准后，在隔离工作区中运行选定路线，并依据单位、坐标轴、峰值、趋势、模态、统计量、不确定性及其他具有科学意义的验收标准评估结果。
5. **为后续研究保留基础。** 记录来源、假设、环境、补丁、命令与结果，使研究者能够比较不同实现、替换数据、开展敏感性分析、调整方法并设计后续研究。

## 从静态图件到研究过程

一张已发表的图件，把输入数据、预处理、公式或代码、参数、随机化过程、实验仪器、统计选择和绘图决策压缩成了一个静态结果。ReproFig 将这条被隐藏的生成链重新展开，使研究者能够把图件作为研究过程的产物来理解，而不是把它当作一张需要模仿的图片。

因此，科研图件复现并不等于描摹已发表图片，也不等于根据像素拟合曲线。可信的复现需要以下证据：

1. 原始输入数据、可按论文构造的仿真数据，或明确声明的替代数据；
2. 作者方法的实现，或能够推导出的实现路线；
3. 参数、预处理、随机化过程和绘图协议；
4. 可用于判断复现成功的科学现象与验收标准；
5. 对应路线所需的运行时、软件包、工具箱、硬件和许可证。

ReproFig 会将这些条件组织成可审计的证据图谱。它不会在信息不足时静默猜测，也不会仅因缺少某张图的作者专用脚本、随机种子或缓存结果，就直接判定无法复现。

## 工作流

```mermaid
flowchart LR
    A[论文 + 目标图件] --> B[理解内容与证据作用]
    B --> C[还原数据-方法-协议链]
    C --> D[制定路线与科学验收标准]
    D --> E[核查路线相关证据与条件]
    E --> F[生成本地报告]
    F --> G{研究者审批}
    G -->|调整路线| C
    G -->|批准路线| H[在隔离工作区中执行]
    H --> I[验证科学现象]
    I --> J[交付可追溯复现成果]
```

### 第一阶段：理解、调查与制定路线

- 确认论文版本和目标图编号；
- 说明每张图展示了什么、为何出现在论文中，以及必须验证什么科学现象或结论；
- 还原图件的数据—方法—协议链和上游依赖；
- 提出明确的复现路线、参数假设、科学范围和验收标准；
- 优先检索官方来源，再考虑第三方实现，并实际审阅相关代码与数据，而不只是收集链接；
- 核验来源、数据集身份、版本、许可证和访问条件；
- 核查本机现有运行时、软件包、工具箱、硬件和兼容执行方案；
- 记录每条路线的资源估算和阻断项；
- 生成自包含的本地 HTML 报告和审批草案，并在完整复现运行前停止。

### 第二阶段：执行并验证已批准的路线

- 校验报告哈希、选定图件、复现路线、参数假设、资源限制和已授权操作；
- 在隔离、可追踪的版本化运行目录中工作，并保留原始代码和数据；
- 记录推导过程、假设、兼容性补丁、命令和结果差异；
- 逐张复现图件，验证其中的科学现象，而不是仅凭视觉相似度判断成功；
- 交付生成的图件，以及重新运行所需的代码、配置、日志、环境信息、验证结果和溯源记录。

## 复现等级

| 等级 | 含义 |
| --- | --- |
| `direct-recompute` | 相关实现与论文案例输入均已获得，可直接复算。 |
| `mechanism-reproduction` | 可重建论文方法或仿真过程，以验证论文报告的机制。 |
| `alternative-validation` | 使用明确声明的替代数据或实现，验证范围更窄的结论。 |
| `editable-reconstruction` | 将流程图或示意图重构为原生可编辑对象；这不属于数值复现。 |
| `original-case-blocked` | 原案例必需的输入、受限资源、仪器或方法细节无法获得。 |

每张图只分配一个复现等级。ReproFig 还会将每项必要条件分别标记为**已核验**、**可推导**、**可合理假设**、**缺失**或**不需要**，明确说明已经复现到什么程度，以及现有证据的边界在哪里。

## 为后续研究建立基础

ReproFig 的目标不止是成功重跑一次。通过明确图件的生成链、参数假设、证据边界和验收标准，它为比较不同实现、替换数据、开展敏感性分析、调整方法和设计后续研究提供一个可追溯的起点。复现本身不会自动产生新研究，但它能让已发表工作变得足够透明，使研究者可以负责任地在此基础上继续推进。

## 安装

可以让 Codex 使用内置 Skill Installer 安装仓库中的 `reprofig/` Skill 目录：

```text
使用 $skill-installer 安装 https://github.com/SciToolsmith/reprofig/tree/main/reprofig。
```

也可以手动安装到个人 Codex Skills 目录：

```bash
git clone https://github.com/SciToolsmith/reprofig.git
mkdir -p ~/.codex/skills
cp -R ./reprofig/reprofig ~/.codex/skills/reprofig
```

安装后的目录中必须包含 `reprofig/SKILL.md`；不要把仓库最外层目录直接当作 Skill 安装。Codex 通常会自动发现新安装的 Skill。如果它没有出现在 `/skills` 中，请重启 Codex。

ReproFig 的辅助脚本需要 Python 3.9 或更高版本，并且只依赖 Python 标准库。目标论文所需的 MATLAB、Python 软件包或其他科研运行环境会被单独核查，不随本仓库分发。

## 使用方法

提供论文 PDF 或 DOI，并指定一至三张目标图：

```text
使用 $reprofig 分析这篇论文中的图 6、图 7 和图 11。
说明每张图展示了什么，还原其数据—方法—协议—验证链，
评估可行的复现路线，并先生成本地报告。
等我批准具体路线后再执行。
```

第一阶段报告包含图件解读及其论证作用、复现等级、证据图谱、代码与数据来源、本机能力核验、访问和许可证状态、参数假设、阻断项、科学验收目标、资源估算与建议路线。经批准的第二阶段运行还会增加生成图件、可复现代码与配置、验证结果、日志、环境信息和溯源记录。

## 执行保障与研究者控制

环境核查、受控下载、隔离环境、资源估算与审批机制，保障的是一条已有科学依据的路线能够被安全执行；它们不能代替对图件的理解，也不能代替对研究过程的还原。

在调查阶段，ReproFig 会先检查本机已有软件，并可在调查预算内审阅体积受控的公开资源或创建隔离的开源环境。大规模或受访问控制的下载、专有软件、接受许可条款、登录、付费、上传、实质性路线变更，以及超出已批准计算、存储、网络或覆盖范围的操作，始终由研究者明确决定。

ReproFig 不会静默执行以下行为：

- 将用户指定的算法替换为未经批准的第三方移植版本；
- 使用其他数据集，却把结果称为原论文实验；
- 安装专有软件或代替用户接受许可证条款；
- 登录账号、付费、上传私有材料或联系第三方；
- 超出已批准的计算、下载、存储或文件覆盖范围；
- 仅凭像素相似度宣称复现成功。
